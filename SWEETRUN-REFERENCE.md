## What SweetRun Is

A maple syrup production platform for serious sugarmakers. Offline-first PWA (Progressive Web App) — no backend, no database, no cloud sync. Everything runs in the browser. One-person project by Damian Brockway.

- **Pricing:** $49.99/year subscription, 14-day free trial
- **Target audience:** Maple producers from hobbyists to large operations (under 100 taps up to 1,000+)

## Where the Code Lives

### GitHub Repository
- **Location on your Mac:** `~/SugarCalc`
- **Remote:** GitHub (push with `git push` from that folder)
- **Main branch:** `main`
- **Auto-deploys to:** Cloudflare Pages on every push to main

### Key Files
| File | Purpose |
|---|---|
| `index.html` | Marketing landing page — the main sweetrun.app page |
| `feedback.html` | Feedback form for producers |
| `app/index.html` | The app shell: head tags, icons, manifest link, loads React and `app.js` |
| `app/src/*.jsx` | React source, split into parts. **Edit these, not app.js** |
| `app/src/parts.json` | The order the parts are joined in before compiling |
| `app/app.js` | Compiled output — generated by `npm run build`, do not edit manually |
| `app/tokens.css` | Every colour, font and size of the Run Sheet design (the Ember palette) |
| `app/runsheet.css` | The app's stylesheet |
| `app/manifest.webmanifest` | Home screen name, colours and icons |
| `app/icons/` | Home screen, tab and maskable icons (option E) |
| `app/photos/`, `app/fonts/` | Header photos and the self-hosted Barlow type |
| `app/sw.js` | Service worker — handles offline caching. Current cache: `sweetrun-v39` |
| `tests/` | `npm test`: formula tests and Run Sheet tests |
| `sitemap.xml` | Submitted to Google Search Console |
| `package.json` | Build config — `npm run build` runs `scripts/build.mjs` |
| `babel.config.json` | Babel preset (React JSX transpiling) |
| `SWEETRUN-REFERENCE.md` | This file |

### Build Process
When you change a part in `app/src/`, compile and test before pushing:
```bash
cd ~/SugarCalc
npm run build          # joins app/src parts (parts.json order) and compiles to app/app.js
npm test               # formula and Run Sheet tests; all must pass
git add app/
git commit -m "your message"
git push
```
Cloudflare Pages also runs `npm run build` on each deploy.

For landing page / feedback.html changes (no compile needed):
```bash
cd ~/SugarCalc
git add index.html feedback.html   # or whatever files changed
git commit -m "your message"
git push
```

**Note:** If you get a `HEAD.lock` or `index.lock` error, run:
```bash
rm ~/SugarCalc/.git/HEAD.lock
```

## Service Worker / Caching

The app uses a service worker for offline support. Current cache name: `sweetrun-v39`. It precaches the app, stylesheets, fonts, icons and header photos, so the whole app works offline after one load. Map tiles have their own cache (`sweetrun-tiles-v1`) that is never cleared.

**File:** `app/sw.js`

If you update the app and users are seeing an old cached version, bump the cache version:
```javascript
const CACHE = 'sweetrun-v40';  // increment this number
```
Then commit and push. Users will get the fresh version on their next visit.
